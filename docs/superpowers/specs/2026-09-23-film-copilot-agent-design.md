# Film Copilot Agent 与分层记忆设计

> 状态：草案，待确认后进入实施计划。
> 日期：2026-09-23
> 前置文档：[画布架构设计](2026-09-22-infinite-media-canvas-design.md)（第 6 节「HTTP 和 Agent 命令接口」、第 10 节「Agent」验收项）

## 1. 目标

给 Film Copilot 加一个能操作画布的 Agent：

1. 用户用自然语言提需求，Agent 在画布上建节点、连线、写 Prompt、发起生成。
2. 用户手动操作和 Agent 操作同时支持，互不覆盖。
3. Agent 有分层记忆：记得当前项目的设定、用户的偏好、过去做过的事，并随使用逐步学习。
4. 用户能看到、修改、删除 Agent 记住的每一条内容。

### 已确认的决定

| 决定 | 结论 |
| --- | --- |
| Agent 框架 | Claude Agent SDK（Python），跑在现有 FastAPI 后端里 |
| 模型 | `claude-opus-5-5`（Claude Opus 5.5），直接调用 Anthropic API（用户本机网络可访问） |
| 查看生成结果 | 需要：Agent 能看到生成出来的图片和视频关键帧，据此判断效果、决定下一步 |
| 自主程度 | 硬规则写在代码里（权限档位），做事风格用 Skill 控制 |
| 默认权限档位 | 只有「发起生成」需要用户确认 |
| 记忆存储 | 第一版全部放在本地 SQLite，自己实现分层；不接入外部记忆框架 |
| 偏好学习 | 用户明确说的直接生效；从操作推断的先标为「待确认」，用户确认后才生效 |

### 第一版不做

- 多用户、多 Agent 协作
- 语音输入
- 看完结果后不经用户同意自动重新生成（重新生成照样走 4.1 的权限确认）
- 外部记忆框架（Mem0 / Graphiti / Letta）

## 2. 总体结构

```
浏览器
 ├─ 画布（已有）
 ├─ Agent 对话面板（新增）
 └─ 记忆管理页（新增）
        │  HTTP + SSE（服务端推送）
        ▼
FastAPI 后端
 ├─ 画布命令服务（已有，Agent 和前端共用）
 ├─ Agent 服务（新增）
 │    ├─ Claude Agent SDK 会话
 │    ├─ 画布工具（MCP 工具，包装画布命令服务）
 │    ├─ 记忆工具
 │    └─ 权限钩子（调用工具前检查）
 ├─ 记忆服务（新增）
 └─ SQLite
```

**核心原则：Agent 没有自己的写入通道。** 它的所有画布改动都调用和前端相同的画布命令服务，连线规则、版本号检查、防重复提交全部照样生效。

## 3. Agent 操作画布

### 3.1 画布工具

工具写成 Claude Agent SDK 的进程内 MCP 工具（`@tool` + `create_sdk_mcp_server`），每个工具只是调用对应的画布命令。

| 工具 | 作用 | 对应命令 | 是否只读 |
| --- | --- | --- | --- |
| `get_canvas` | 读取画布：节点、连线、生成状态；可只返回选中节点及其上下游 | 读取快照 | 是 |
| `get_node` | 读取单个节点详情（含 Prompt、参数、参考素材） | 读取快照 | 是 |
| `view_asset` | 查看某个节点的内容：图片直接返回；视频返回首、中、尾 3 张关键帧和时长 | 读取素材 | 是 |
| `create_nodes` | 批量建节点（可带标题、Prompt、参数、位置） | `create_node` | 否 |
| `update_node` | 改标题、Prompt、参数、便签文字 | `update_node` | 否 |
| `connect` / `disconnect` | 建立 / 断开连线 | `connect_nodes` / `disconnect_nodes` | 否 |
| `move_nodes` | 调整位置、自动排版 | `move_nodes` | 否 |
| `duplicate_nodes` | 复制节点 | `duplicate_nodes` | 否 |
| `delete_nodes` | 删除节点或连线 | `delete_elements` | 否 |
| `generate` | 对指定节点发起生成 | `start_generation` | 否（花钱） |
| `wait_for_generation` | 等待生成完成，返回结果图片（视频为关键帧）或失败原因 | 读取任务 | 是 |

- 关掉 SDK 自带的文件读写、命令行等工具，Agent 只能用上面这些和记忆工具。
- 工具出错时返回清楚的中文说明（例如「图片节点不能接收视频参考」），让 Agent 自己调整，而不是中断。
- 节点较多时，`get_canvas` 返回精简版（每个节点只给 ID、类型、标题、Prompt 前 80 字、状态），需要时再用 `get_node` 看详情，避免占满上下文。

### 3.2 查看生成结果

- 生成完成后，`wait_for_generation` 直接把结果返回给模型：图片缩小到长边 1024 像素，视频抽取首、中、尾 3 帧（用 ffmpeg，同样缩到 1024 像素）。
- 缩小的目的是控制费用：图片按像素计费，原图（2K）比缩略图贵很多，而判断构图、风格、内容是否符合要求用 1024 像素已经够了。
- Agent 看完后在回复里给出简短评价，例如「第 2 张最接近你要的胶片感，第 3 张兔子耳朵变形了」，并提出下一步建议。
- 用户也可以让 Agent 看画布上任意已有的图（包括上传的参考图），例如「看看这张图的风格，照着写 Prompt」。
- 一轮对话里看过的图，在长对话压缩时只保留文字描述，不重复计费。

### 3.3 标记来源

- `CommandEnvelope` 增加两个可选字段：`actor`（`user` 或 `agent`）和 `agentRunId`。
- 画布事件和命令日志都记录这两个字段。前端据此：
  - 给 Agent 本轮改动过的节点加一圈高亮，悬停显示「Agent 修改」
  - 在对话面板里把每一步改动列出来，点击可定位到对应节点

### 3.4 和用户同时操作

- Agent 每次写入都带上它最后看到的版本号。
- 用户在这期间改了画布，版本号对不上，命令会被拒绝。这时工具自动重新读取画布，把「用户刚改了哪些节点」告诉 Agent，由 Agent 决定是否继续，**不会覆盖用户的改动**。
- 对话面板有「停止」按钮，点击后当前工具调用结束，Agent 不再发起新操作。

### 3.5 按任务撤销

- 新增 `agent_run_changes` 表：Agent 每执行一条写入命令，就记录受影响节点和连线在改动前、改动后的状态。
- 「撤销本轮」按倒序恢复改动前的状态：
  - Agent 新建的节点 → 删除
  - Agent 修改的节点 → 恢复原值
  - Agent 删除的节点 → 重新创建（使用原 ID）
- 如果某个节点在 Agent 改完之后又被用户手动改过，这个节点跳过、不恢复，并在面板里提示「这个节点你之后改过，已保留你的版本」。
- 已经发起的生成不会被撤销，已花掉的额度也不能退回；撤销只移除生成结果和节点的关联。

## 4. 权限与 Skill

### 4.1 权限档位（硬规则，代码实现）

用 Claude Agent SDK 的调用前钩子（PreToolUse hook）实现：每次调用写入类工具之前，都要先经过这一关。

| 档位 | 行为 |
| --- | --- |
| 每步确认 | 所有写入操作都要用户确认 |
| **只确认生成**（默认） | 画布编辑直接执行；`generate` 和 `delete_nodes` 需要确认 |
| 全自动 | 都不确认，但仍受下面的上限约束 |

不管哪个档位，以下限制始终生效：

- 单轮任务最多发起的生成次数（默认 4 次），超出必须确认
- 视频生成永远需要确认（单次成本高）

**确认流程**：钩子暂停工具调用 → 后端通过 SSE 推送确认请求 → 对话面板显示「将生成 3 张图，节点：…」和确认 / 拒绝按钮 → 用户选择后，钩子放行或返回「用户拒绝」给 Agent。

档位在画布设置里切换，按项目保存。

### 4.2 Skill（软规则，控制做事风格）

- 放在项目的 `.claude/skills/` 目录，通过 SDK 加载。
- 第一版内置：
  - `plan-first`：先用一两句话说明打算怎么改，再动手；改动超过 5 个节点时先列方案等用户同意
  - `storyboard`：把一段剧情拆成分镜节点，按顺序排版、连好参考
  - `prompt-craft`：写 Seedream / Seedance Prompt 的要点
- Skill 只影响 Agent 的判断和习惯，**不能**绕过 4.1 的权限档位。

## 5. 分层记忆

### 5.1 分层

| 层 | 范围 | 存什么 | 何时写入 | 何时读取 |
| --- | --- | --- | --- | --- |
| L0 工作记忆 | 当前对话 | 画布状态、最近的对话 | 不单独存储 | 每轮自动放进上下文 |
| L1 项目记忆 | 当前项目（画布） | 设定集：角色、风格、基调、已定的决定、禁忌 | Agent 用记忆工具写入；用户在管理页编辑 | 每次会话开始时全部载入 |
| L2 用户偏好 | 跨项目 | 常用参数、审美偏好、Prompt 写法、沟通习惯 | 用户明说；从操作推断（待确认） | 会话开始时载入已确认的条目 |
| L3 长期经历 | 跨会话 | 每次会话的摘要：做了什么、试了什么、选了哪个 | 会话结束时自动生成 | 按需搜索（`recall` 工具） |
| L4 做事套路 | 跨项目 | 用户确认过的可复用流程 | 用户确认后保存成 Skill | 由 Skill 机制加载 |

「范围」决定这条记忆在哪里生效：L1 只在当前项目里生效，L2、L3、L4 在所有项目里生效。

### 5.2 数据结构

新增 `memories` 表：

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `layer` | `project` / `preference` / `episode` |
| `canvas_id` | 项目记忆填对应画布，其余为空 |
| `category` | 分类，例如 `character`、`style`、`decision`、`params`、`prompt_style` |
| `content` | 一句话内容，例如「主角是一只米白色垂耳兔」 |
| `source` | `user_stated`（用户说的）/ `agent_inferred`（推断的）/ `user_edited`（用户在管理页改的） |
| `status` | `active`（生效）/ `pending`（待确认）/ `superseded`（被新条目取代）/ `rejected`（用户否决） |
| `evidence_json` | 推断依据，例如「最近 3 次都选 16:9」及对应的节点 ID |
| `superseded_by` | 被哪一条取代 |
| `created_at` / `updated_at` / `last_used_at` | 时间 |

搜索：SQLite 自带的 FTS5 全文检索（按关键词搜）。L3 条目变多、关键词搜不准时，再加 `sqlite-vec` 扩展做按意思相近的检索，表结构不变。

### 5.3 记忆工具

| 工具 | 作用 |
| --- | --- |
| `remember` | 写一条记忆（指定层、分类、内容、来源） |
| `update_memory` | 修改一条记忆；内容冲突时把旧条目标为 `superseded`，而不是直接覆盖 |
| `forget` | 用户要求忘记时删除 |
| `recall` | 按关键词搜索 L1–L3 |

**写入规则**（写进系统提示词）：
- 用户明确表达的偏好或设定 → 直接写入，`source = user_stated`，`status = active`
- 自己推断的 → `source = agent_inferred`，`status = pending`，必须附上依据
- 一次性的信息不记（例如「这张先放左边」）
- 和已有条目冲突时，用 `update_memory` 标记取代，并在回复里告诉用户「我把 X 更新成了 Y」

### 5.4 从操作推断偏好

后台定期（每次会话结束时）分析最近的操作记录，找出重复出现的模式：

| 信号 | 例子 | 推断 |
| --- | --- | --- |
| 参数选择 | 最近 5 次图片生成，4 次选 16:9 | 「偏好 16:9 画幅」 |
| 保留 / 删除 | 连续删除偏卡通风格的结果 | 「不喜欢卡通风格」 |
| 手动修改 Agent 的结果 | 多次把 Agent 写的英文 Prompt 改成中文 | 「Prompt 偏好用中文」 |
| 重复工作流 | 多次「出图 → 复制 → 改 Prompt → 对比」 | 候选的做事套路（L4） |

- 推断结果一律以 `pending` 写入，在记忆管理页顶部显示「有 N 条新发现待确认」。
- 被否决的推断标为 `rejected`，同样的模式不再重复提出。
- 阈值（例如「5 次中出现 4 次」）写在配置里，先保守，后面按效果调整。

### 5.5 载入上下文

每次会话开始，系统提示词依次放入：

1. 固定指令（角色、工具使用规则、记忆写入规则）
2. 当前权限档位（让 Agent 知道哪些操作需要确认）
3. L1 项目记忆：全部 `active` 条目，按分类分组
4. L2 用户偏好：全部 `active` 条目
5. L3 最近 3 次会话摘要

L1 + L2 超过约 2000 字时，按 `last_used_at` 只保留最近常用的，其余靠 `recall` 按需查。`pending` 状态的条目**不**放进上下文，确认之前不影响 Agent 的行为。

### 5.6 会话结束时

1. 生成本次会话摘要，写入 L3
2. 运行 5.4 的偏好推断
3. 更新被用到的记忆的 `last_used_at`

## 6. 界面

### 6.1 Agent 对话面板

- 画布右侧可收起的面板，快捷键 `⌘J`。
- 选中节点后再提需求，这些节点会作为「当前关注」一起发给 Agent。
- 显示内容：
  - Agent 的回复（流式显示）
  - 每一步工具调用，写成一句话，例如「新建 3 个图片节点」「连接 便签 1 → 图片 2」，点击可定位节点
  - 待确认的操作卡片（确认 / 拒绝）
  - 本轮结束后的「撤销本轮」按钮
- 顶部显示当前权限档位，可以切换。

### 6.2 记忆管理页

- 从左侧栏进入，分「本项目」和「我的偏好」「历史会话」三个标签。
- 每条记忆显示内容、来源标签（我说的 / Agent 推断 / 我改过的）、更新时间；可以编辑、删除。
- 「待确认」区：显示推断内容和依据，按钮为「确认」/「不对」/「改一下再确认」。
- 被取代的旧条目默认折叠，可以展开查看历史。

## 7. 后端接口

| 接口 | 作用 |
| --- | --- |
| `POST /api/agent/sessions` | 新建会话（绑定画布） |
| `POST /api/agent/sessions/{id}/messages` | 发送用户消息，附带选中节点 ID |
| `GET /api/agent/sessions/{id}/stream` | SSE：回复片段、工具调用、确认请求、结束 |
| `POST /api/agent/runs/{id}/confirm` | 确认或拒绝某个待确认操作 |
| `POST /api/agent/runs/{id}/stop` | 停止当前任务 |
| `POST /api/agent/runs/{id}/undo` | 撤销本轮 |
| `GET/POST/PATCH/DELETE /api/memories` | 记忆的增删改查，支持按层和状态筛选 |

Agent 会话在后端进程内运行。Anthropic API Key 放在 `.env` 的 `ANTHROPIC_API_KEY`，模型 ID 放在 `AGENT_MODEL`（默认 `claude-opus-5-5`），和 Replicate Token 一样不提交到 Git。

## 8. 分阶段实施

| 阶段 | 内容 | 完成标准 |
| --- | --- | --- |
| 1. Agent 能操作画布 | 画布工具、对话面板、SSE 流式显示、来源标记与高亮、权限档位与确认、停止、按任务撤销 | 能说「用这张兔子图做 3 个不同风格的版本」，Agent 建节点、连线、写 Prompt，确认后生成；撤销能恢复原状 |
| 2. 项目记忆与用户偏好 | `memories` 表、记忆工具、上下文载入、记忆管理页 | 告诉它「主角是米白色垂耳兔」，新开会话后它仍然知道；管理页能看到并修改 |
| 3. 长期经历与偏好推断 | 会话摘要、`recall` 搜索、操作模式推断、待确认流程 | 连续几次都选 16:9 后，管理页出现待确认条目；确认后新会话默认用 16:9 |
| 4. 评估与扩展 | 根据实际效果决定是否接入向量检索或外部记忆框架；做事套路自动沉淀成 Skill | 按需求决定 |

## 9. 测试

- **画布工具**：用假的 Anthropic 客户端（不真正调用模型）直接调用每个工具，验证命令、来源标记、错误说明。
- **并发**：模拟 Agent 写入过程中用户改了同一节点，验证 Agent 的写入被拒绝、用户的改动保留。
- **撤销**：新建、修改、删除三类改动都能恢复；用户后来改过的节点被跳过。
- **权限**：各档位下 `generate` 是否被拦截；超过次数上限时是否强制确认。
- **记忆**：冲突时标记取代而不是覆盖；`pending` 条目不进入上下文；被否决的模式不重复提出。
- **端到端**：用真实模型跑 3–5 个固定任务，人工检查结果；这部分不进自动测试（有成本、结果不固定）。

## 10. 待定问题

1. 一个项目 = 一张画布吗？以后要支持一个项目下多张画布的话，L1 的范围需要改成按项目 ID。
2. 对话历史保存多久？L3 摘要永久保留，完整对话记录是否定期清理？

已定：Agent 查看生成结果（见 3.2）；模型使用 `claude-opus-5-5`，模型 ID 放在配置里，以后可以改。
